Junction admission now samples conflicts more frequently while preserving its original safety margin, and independent crossings can continue past a stopped stream. Spawn rates, map scale and signal timings accept typed values. Each spawn node can exclude itself as the destination for its own new trips. See [controls and measured capacity](docs/JUNCTION_CAPACITY.md), [startup queue fixes](docs/STARTUP_JUNCTION_FIX.md) and [native lane editing](docs/NATIVE_LANES.md). The SUMO workflow below is retained as an optional legacy export path.

**Wassup5 road setup and real SUMO:** use `build/traffic_roads.exe` → **Load Wassup5 road preset** → **Build and open real SUMO**. The preset uses 0.73 m/pixel and the confirmed one-way/two-way layout. The editor now sketches multi-lane one-way/two-way roads, generates junction connections, and exports runnable SUMO projects. See [the road authoring and SUMO guide](docs/SUMO_ROADS.md) for setup, controls, validation results and model boundaries.

The viewer uses an explicit node-and-connection editor:

- **Nodes and paths → Place nodes**: click the road to place isolated nodes. Placing a node never creates a connection or enables spawning.
- **Left-click a node** to open its settings popup. Mark **Spawn point**, adjust its independent **Vehicles / s** rate, or change local **Turn braking**. These settings apply live; a spawn node needs a connected route long enough to fit its vehicle.
- **Connect to node…**: click another node to create a directed connection. Existing nodes stay in place. Repeating the same connection does not duplicate it.
- **Sever outgoing connection…**: click the other endpoint to remove that directed connection while retaining both nodes. The reverse connection, if any, remains separate. Topology changes pause and reset traffic.
- **Ctrl + left-click** nodes in travel order to select a connected path. Each subsequent node must be directly connected from the previous one. Selected connections turn yellow; **Clear selected path** starts a fresh selection. The popup also offers **Start path selection here**.
- The selected path's **Turn smoothness** slider changes the radius of turns leaving those connections. Higher values round the corner earlier with wider arcs. Changes reset traffic. The mask, segment lengths, vehicle dimensions and corridor width still limit the arc; smoothing never permits crossing a divider or leaving the road. Use **Turn braking** independently to control slowdown, with Smooth mixed traffic enabled.
- **Save/Load node network** uses `.nodes` files and preserves isolated nodes, explicit connections, spawn flags/rates, braking and smoothness. **Import old .lanes file** converts older networks, preserving their marked entries. Terminal nodes are destinations. Vehicles still randomly select reachable endpoints after merges.

Spawn clocks belong to nodes, including nodes with multiple outgoing connections, so adding a branch does not multiply its spawn rate. Blocked insertions are skipped; the existing 100-active-vehicle cap remains. No connection is inferred merely because distinct nodes are nearby. Newly authored networks require manually marked spawn nodes; the built-in demo retains its two marked entries.

C++17 traffic engine and Windows ImGui viewer. Vehicles move in continuous meter coordinates over a PNG drivable mask, with oriented rectangular bodies, per-class Gaussian attributes, minimum pairwise spacing, randomized routes, gap-aware replanning, and timed traffic lights.

The viewer now starts with **two opposing directed lanes** on the built-in curved road. Lane-based insertion replaces yellow spawn markers: vehicles start fully on an entry lane, tangent to its direction, at rest, only when the insertion footprint and spacing are safe. On a loaded PNG, use **Directed lanes → Draw lane centerline**, click points in travel order, and finish the lane. Draw a separate parallel centerline in reverse travel order for opposing traffic. Width, speed cap and entry permission are set before finishing. Endpoint connections within 0.5 m are inferred in the forward direction; immediate U-turns require explicit API connections. Terminal lanes are exits. The PNG remains the physical drivable mask; lane directions cannot be inferred reliably from red pixels alone.

Save the topology with **Save lanes** to a `.lanes` file alongside the PNG, and load it with **Load lanes (reset traffic)** after loading the image. Lane arrows show direction. Yellow PNG pixels remain walkable legacy metadata but no longer create departures in the viewer. The older engine API retains marker-based spawning only when no lane network has been configured.

Routes use a directed graph and positive travel-time/congestion costs with small seeded jitter, reaching a terminal lane even when another branch contains a cycle. Vehicle width filters unusable branches. Vehicles retain their assigned route and body corridor: free-mask reroutes, passing detours, reversing and gravitational drift cannot send them into an opposing lane. Red queues follow their existing lane trajectory instead of spreading across directions. Whole-turn corridor reservations are replaced by incremental body admission for lane vehicles; genuine junction conflicts can still use negotiated turn priority. Opposing vehicle envelopes that cannot satisfy the smaller-preference clearance are refused at insertion until compatible space is available, avoiding a predictable head-on deadlock. This is deliberately conservative and may reduce admitted demand on narrow roads.

Gentle centerline bends use smoothed body tangents rather than generating tight miniature fillets at every map sample, avoiding artificial repeated braking. Sharper junction turns retain rounded geometry. Vehicles sharing the same directed route remain a following platoon rather than taking turns through every curve. Lane speed caps remain enforced when live per-vehicle speed settings are changed.

This is a SUMO-inspired lane-network foundation, not a SUMO importer or full replacement. Automatic lane changing, SUMO XML files, scheduled departure queues and traffic assignment zones are not implemented. Failed insertion returns false; subsequent automatic requests try again rather than retaining a SUMO demand queue. The lowest speed cap on an assigned route currently limits the trip. See [SUMO vehicle insertion](https://sumo.dlr.de/docs/Simulation/VehicleInsertion.html) for the reference model. Engine APIs: `setLanes`, `lanes`, `spawnOnLane`, `saveLanes`, and `loadLanes`; edit networks on an empty/reset simulation. Lane tests cover opposing streams, safe incompatible-pair deferral, connected/cyclic routing, file round trips and curved signal traffic for seeds 7/42/123, with deletion disabled and pairwise clearance checks.

## Hand-drawn masks and scale

Draw arbitrary road outlines in a PNG, up to 16 million pixels. Pixels describe the mask, not individual vehicle occupancy slots. Use this palette:

| Pixel | Interpretation |
| --- | --- |
| Red `#FF0000` | Drivable road |
| Yellow `#FFFF00` | Spawn point or region |
| Green `#00FF00` | Destination point, region, or exit line |
| Blue `#0000FF` | Traffic-light stop line |
| Pink `#FF00FF` | Solid lane divider; vehicles cannot cross |
| Black, white, unrecognized colors, or alpha below 128 | Non-drivable |

Use opaque exact colors for reliable results; dominant-color thresholds accept some antialiasing and common pink shades. Paint markers over the road: yellow, green and blue pixels remain drivable. Pink is a physical obstacle checked against the entire vehicle body and its turning sweep. Each pixel covers the configured **Meters / pixel**. A 1,000-pixel-wide mask at 0.1 m/pixel is 100 meters wide. Vehicle length, width and preferred gap are meters, speed is m/s, and acceleration is m/s². **Apply scale and reset** changes the map scale while preserving physical vehicle dimensions.

The viewer defaults to a curved demo mask at 0.5 m/pixel. Load `examples/annotated-map.png` for an example with two spawns, an exit line, blue stop lines and a solid divider. `examples/curved-mask.png` uses the same new palette. Place spawns far enough from walls for the largest vehicle. Green exit lines can lie at road edges: vehicles complete when their body reaches the selected green region, with a center target offset to keep the body on the road. A spawn is rejected if its sampled body cannot fit or reach its destination.

Each eight-connected blue component becomes one finite, straight stop line fitted to its principal axis. Draw separate straight strokes and leave a gap between independent lights. Pink dividers can split a blue stroke into independent signals. Defaults are 10 seconds green, 2 yellow and 12 red; edit timings in the traffic-light panel. Curved or branched blue strokes should be replaced by separate straight lines.

In **Map authoring**, choose a tool: drag to paint roads or erase, click to place a spawn, or click two endpoints for an exit, signal or divider. Paint roads first. Marker tools preserve walls and dividers. Road, spawn, exit and divider edits pause and reset traffic; signal placement leaves the running simulation intact. Use **New blank map** to start from scratch, and **Save PNG** to export the color mask. The PNG stores geometry; meters-per-pixel, signal timing and vehicle profiles remain runtime settings. Choose the scale again when loading the saved PNG. Manually placed signals remain independent during the session even when touching; PNG reimport groups touching blue pixels, so leave a gap between signals you want to reload separately.

Older white-road/green-spawn/red-destination files require explicit conversion:

```sh
build/traffic_demo --convert-legacy old.png converted.png
```

The engine also accepts `MapPalette::Legacy` as the third `Map::fromPng` argument. Do not apply legacy conversion to files already using the new palette.

## Vehicle population and gaps

Use **Vehicle spawn mix (%)** to enter the percentages of bikes, motorbikes, cars, trucks and buses. The total must be 100%; click **Apply mix** to update future spawning while traffic runs. **Normalize to 100%** proportionally scales draft values; **Revert mix** restores the currently applied values. Zero excludes a class and 100% selects only that class. These are random spawn-attempt probabilities: rejected large vehicles and occupied spawn regions can bias the observed accepted population. Existing vehicles keep their class and attributes. The engine API is `spawnPercentages()` / `setSpawnPercentages(array)`; the existing per-profile weight API remains supported.

Expand **Vehicle population**, select a class, and edit the mean and standard deviation for speed, acceleration, body length, body width, and preferred gap. Its applied spawn percentage is displayed read-only. Default requested percentages are approximately 18.18% bikes, 27.27% motorbikes, 36.36% cars, 9.09% trucks and 9.09% buses. Vehicle defaults are illustrative and editable:

| Class | Length mean (m) | Width mean (m) | Gap mean (m) | Speed mean (m/s) |
| --- | ---: | ---: | ---: | ---: |
| Bike | 1.8 | 0.60 | 0.4 | 5 |
| Motorbike | 2.1 | 0.75 | 0.5 | 9 |
| Car | 4.5 | 1.80 | 1.5 | 11 |
| Truck | 8.0 | 2.50 | 2.0 | 8 |
| Bus | 12.0 | 2.50 | 2.0 | 7 |

Each attribute is independently sampled once at spawn from its class's normal distribution. Standard deviation zero gives the exact mean. Gaussian tails are clamped: length 0.2–30 m, width 0.15–5 m, preferred gap 0–20 m, speed 0.05–50 m/s, acceleration 0.05–100 m/s². Clamping and rejection of bodies that do not fit can change the observed population moments. Plots show normalized Gaussian shapes before clamping, not measured histograms.

Changing a profile affects future spawns. **Resample active vehicles** applies the current per-class speed/acceleration distributions to existing traffic. Existing body sizes and gaps remain fixed to avoid introducing overlaps. Click a vehicle to inspect its actual sampled size/gap and edit its individual desired speed and acceleration. Vehicles are drawn at physical scale, with a heading marker. Colors distinguish classes. **Show preferred clearance** draws each vehicle's own rounded clearance envelope; the actual pairwise spacing uses the smaller preference, so those individual envelopes may overlap legally.

For every pair A/B, the engine requires:

```text
Euclidean distance between rectangle edges >= min(A.preferredDistance, B.preferredDistance)
```

There is no one-vehicle-per-pixel rule. Whole rectangles, rotation sweeps, map walls and that pairwise minimum decide whether a move fits. Vehicles look ahead and periodically replan around occupied bodies, including required clearance, so a smaller vehicle can take a usable lateral gap around a slower vehicle. They never teleport into a gap or ignore another vehicle's body. Passing succeeds only if a connected, footprint-safe path exists at the navigation sampling resolution.

## Traffic lights

Enable **Place stop line on map**, choose its orientation and length in meters, and click the map once for each independent light. Placement stays active for adding multiple lights; turn it off when finished. The two-click **Traffic-light line** authoring tool also supports arbitrary orientations. Adding or removing a signal preserves active vehicles, their positions/speeds, and the simulation clock.

Choose **Selected light** (L0, L1, etc.), or click a light in Inspect mode, to edit that light's enabled state, green/yellow/red durations and phase offset. Drag the duration fields or Ctrl+click to type seconds. Changes apply immediately while traffic runs, without resetting any vehicle or the clock. Green/red durations accept 0.1–3600 seconds; yellow accepts 0–3600 seconds. Each light uses `(simulation seconds + offset) modulo cycle length`, so changing a duration may change its current phase immediately. Other lights keep their own durations. The selected light has white endpoint rings and each line is colored by its phase. Reset restarts phase clocks and preserves configured lights/profiles.

Each light controls crossings of a finite stop-line segment from either direction. Yellow and red prevent a vehicle's front or turning body entering the line; a vehicle already straddling it may clear after the phase changes. Swept checks prevent fast vehicles skipping a red line. Cover the whole approach width to prevent a route around the end of a short line. Lights are independent; use equal cycle lengths and offsets to coordinate multiple approaches. There is no automatic intersection conflict controller or lane-direction inference from a painted mask. A typical two-approach setup uses 10 s green, 2 s yellow, 12 s red, with offsets 0 and 12 s. The two yellow periods then act as clearance intervals.

Signal placement updates the blue mask pixels and can be exported with **Save PNG**. Timings, linked-exit permissions, spawn mix and profile edits remain in-memory settings. Loading another mask imports its blue stop lines as normal signals. Scale changes preserve stop and linked-exit image locations.

**Draw permissive light + exit** creates a route-specific red/yellow exception. Click both endpoints of the stop line, then both endpoints of its linked exit line. The staged light is installed only after all four clicks succeed; placement leaves running traffic intact. The same tool is available in **Map authoring**. For an existing signal, select it and choose **Set allowed exit for this light** or **Redraw allowed exit**, then click the two exit endpoints. **Remove red/yellow permission** restores normal behavior without deleting the light.

The stop line keeps its ordinary timed red/yellow/green phase. Its linked exit is a cyan overlay labeled with the same light ID. A vehicle is exempt from that light's red/yellow only if its actual remaining planned path crosses this stop line and subsequently crosses the linked exit line. Crossing the exit earlier, driving parallel along it, or merely having a destination beyond it does not grant permission. A queued vehicle's cached departure path participates in the decision, so a live permission edit can release a qualifying red-light queue. Nonqualifying vehicles still wait normally. The permission applies only to its own light; other signals, physical bodies, preferred gaps, mask walls and solid dividers retain their normal constraints. A permitted follower may still have to wait behind a nonpermitted leader.

The linked exit does not create a destination or a lane boundary, and is not painted into the PNG mask. It and the per-light timing remain session settings and survive simulation Reset; PNG export stores stop-line geometry only. Loading another PNG recreates normal signals without those links. The engine fields are `TrafficLight::permissive`, `allowedA`, and `allowedB`; `routePermitsRed(entity, light)` exposes route eligibility. Select a vehicle to inspect its eligibility for the currently selected permissive light.

**Spread across red lights** is enabled by default. Vehicles whose routes cross a red/yellow stop line seek free positions across the usable approach, filling the front row before rows behind it. Position selection checks the real mask, vehicle dimensions and the smaller pairwise preferred gap. Narrow vehicles also probe the exact edges of existing positions to use fitting gaps. A curved, collision-checked approach brings each vehicle into place; every part of that approach remains on the approach side of the stop line. A narrow road retains a single queue when multiple bodies cannot fit abreast.

The stop target is the nearest currently required red/yellow light **along the remaining route**, not the nearest line by straight-line distance or list order. The search includes a queued vehicle's cached departure route and excludes lights it is permitted to pass. Nearby vehicles first follow their existing road trajectory up to a footprint-safe stop about 0.15 m before the line; the route is clipped at the stop instead of reserving a turn beyond it or steering directly across a curved mask. Lateral spreading remains the fallback when that route's front position is occupied. This natural route approach also works when spreading is disabled.

Phase changes trigger a fresh target check. A nearer red appearing on the route replaces a farther stop target. When the current light turns green or grants the vehicle permission, its approach and cached departure are joined continuously without forcing a stop at the old holding point. Waiting vehicles recheck for vacated forward positions and move closer when their footprint and required pairwise gaps fit; lateral-only shuffling is avoided. The original destination remains unchanged. Select a vehicle to see its nearest required signal and distance along the route; its current assigned queue target is marked in amber.

Signal queues are planned as a group before the physics step moves anyone. Eligible vehicles are processed nearest-first along their routes, without the old one-route-per-substep limit. Simulation seconds, signal phases, vehicle positions/speeds and stopped-time counters remain fixed during this planning pass. Claimed final positions act as virtual obstacles for subsequent plans, including claims from other approaches; the planner can use space that an already planned vehicle will vacate. Front-row gaps are filled first, then rear positions are fitted along the road behind claimed footprints. Larger queues are not limited to three fixed rows. If a road or real obstacle prevents a valid approach, that vehicle keeps its safe existing route and can be reconsidered later.

After planning, all vehicles advance through the same simulation intervals. Signal approaches use per-step swept collision checks and ordinary queue following rather than reserving the entire approach corridor until one car finishes. Different lateral waiting positions are not incorrectly treated as a single lane. Physical vehicle bodies, preferred gaps, stop lines, mask boundaries and non-queue maneuver reservations remain enforced. The viewer excludes batch-planning wall time from subsequent real-time catch-up, so a slow planning pass does not fast-forward the simulation afterward. **Plan all signal queues now** prepares eligible routes without advancing time, even while paused; the panel shows planning passes, last route count and milliseconds. The engine API is `planSignalQueues(force)` with corresponding planning counters/timings. Regression tests verify frozen-clock planning, concurrent progress of 4- and 36-vehicle groups, safe target separation and opposing approaches.

These positions are temporary holding points, so arrival at one does not count as completing a trip. Vehicles brake toward their chosen position, then wait for green. Their original destinations remain unchanged. On release, they use a prevalidated exit, moving forward before merging when the map permits it. Removing or disabling a signal also releases its queues. A red-light wait releases unused turn reservations so other vehicles can use adjacent road space; paused arcs reacquire only their remaining sweep. Disabling spreading prevents new position assignments; existing assignments finish safely. The viewer reports queue placements and distinguishes vehicles filling stop-line space from those waiting in position.

## Physics and navigation

**RTS-style routing** is enabled by default. The design is inspired by Ensemble's description of separate large-area, short-distance and unit-obstruction systems for Age of Empires II; it is an original implementation for this vehicle engine. See [the developer's July 2000 article, pages 36–37](https://media.gdcvault.com/GD_Mag_Archives/GDM_July_2000.pdf).

The static mask is partitioned into small connected areas within approximately four-meter sectors (sector size is limited to 4–64 image pixels). An area-adjacency graph gives fast connectivity checks, so disconnected destinations are rejected before a detailed search. Reverse distance fields on that graph are cached for up to 16 destination areas and reused across vehicles with nearby goals. The field guides the detailed, heading-aware search softly: it cannot prohibit a larger vehicle from using another area when a suggested shortcut does not fit. Current vehicle occupancy adds a bounded congestion cost to global searches.

Short-range avoidance looks ahead along the current straight corridor. When a slow vehicle blocks it, the engine tries bounded, consistent-side bypasses, rejoins the original forward route, and retains the final destination. Each candidate is converted into the same curved-motion representation and checked against the mask, physical vehicle boxes, spacing, stop lines and active reservations before acceptance. Successful local repairs preserve current position, heading and speed; the final movement gate still checks every actual step. Committed arcs are completed before another local repair. Persistent blockage falls back to a traffic-aware global search and the existing checked reverse recovery.

**Reissue destination while moving** adds a periodic RTS-style move command to the original final endpoint. It is enabled by default with **Moving refresh (s)** set to 3 seconds (editable live from 0.25–120 seconds). The timer accumulates actual forward-moving simulation time above 0.05 m/s; stationary/red-light time does not count. Reversing recovery, signal queues, routes crossing a currently red/yellow stop line, assigned signal approaches and committed turn reservations defer the command until safe. This prevents periodic global searches disrupting normal red-light spreading. Overdue eligible vehicles are served by greatest accumulated moving time, at most one attempt per physics substep. The refresh rebuilds the static-mask route with zero random traversal noise, leaving vehicle avoidance to the normal RTS local system instead of creating large global detours around temporary traffic. The new curve starts at the current position and heading, retaining speed and the final endpoint. A failed search keeps the current path and retries after another interval of movement. The timer restarts when this option, its interval, or RTS mode changes. Disabling RTS mode also disables reissues.

The routing panel displays successful destination refreshes and attempts; the vehicle inspector displays its successful refresh count and moving timer. Engine settings are `RoutingSettings::refreshMovingRoutes` and `movingRefreshInterval`; counters are `destinationRefreshes()` / `destinationRefreshAttempts()`. This supplements local avoidance rather than removing physical spacing, signals or reservation admission checks. Short intervals increase pathfinding cost; pause and time scale apply consistently with the simulation clock.

A refreshed route only replaces the current route when it saves more than both 0.5 m and 5% of remaining travel distance. Otherwise the command keeps the already efficient route, avoiding changes caused by small navigation-sampling differences. A new curved entry must obtain its reservation before replacing a moving route; if it cannot, the old route remains intact. Successful reissue counters include commands that retain an already efficient route. Refresh searches preserve the random stream used for future spawning and randomized routes.

Active local bypasses are an exception to those conservative refresh rules. They are reconsidered after the shorter of **Moving refresh** and **Local update** moving-time intervals, even while holding their own maneuver reservation. A safe shortcut saving over 0.05 m can replace an obsolete bypass without meeting the ordinary 5% threshold. The return curve blends from the current position, heading and speed over a short initial segment (at most twice vehicle length, with a 4 m minimum), then continues toward the original endpoint. The return/following corridor is checked against current bodies, minimum pairwise gaps, other vehicles' reservations and stop lines. A still-blocked return keeps the original bypass. A clear return atomically replaces the old path and reservations, including when already turning. Ordinary committed road turns and assigned signal queues remain protected. A red light farther down the route does not prevent this local correction, but the checked return cannot cross its red/yellow stop line.

When passing space is unavailable, moving queues are followed with a speed target based on the leader's speed and available gap, with braking at twice the follower's sampled acceleration. Signal and maneuver waits propagate through queues. Use the routing panel to set **Look ahead**, **Local update** interval and **Avoid congestion** weight, or disable RTS routing to compare with the prior global-replanning behavior. The viewer displays local-detour/global-plan/cache-hit counts and the selected vehicle's following/detour state. Routing settings take effect during the run and survive reset; cache contents rebuild with a new simulation or mask.

An aligned leader still accelerating toward a comparable cruising speed is followed instead of immediately overtaken. Local passing compares a 1.5-second acceleration forecast as well as cruising targets; an actually blocked or persistently stationary leader can still be bypassed. Full traffic-aware route repairs in RTS mode require actual blocked motion, rather than triggering just because a longer look-ahead probe overlaps the current position of a moving leader. Ordinary following does not become a global detour unless the vehicle remains stationary for over three seconds; signal and maneuver queues stay protected. A regression runs the exact built-in map, seed, spawning schedule and signal preset through its first ten seconds, checking that nearby route prefixes do not loop backward or turn sideways around accelerating traffic. The viewer and test share the same demo-map generator.

Signal-wait propagation is rebuilt each physics step from currently red/yellow stop lines and assigned signal slots. Old indirect wait flags cannot circulate indefinitely through mutually blocked vehicles after the actual signal clears. Legitimate followers still inherit the current signal wait and retain their normal stopped-time statistics.

Use **Run/Pause**, **Advance step**, **Reset**, time scale, spawn rate and manual spawn. The side panel scrolls. Automatic spawning caps the viewer at 100 active vehicles. The seed takes effect on reset. Identical seeds and call sequences reproduce results with the same toolchain; changes to accepted spawns or profiles change subsequent draws.

For CPU-limited machines, choose **Clock mode → Manual steps (on demand)**. Set **Seconds / step** (0.01–60 simulation seconds), then click **Advance step**. The simulation advances only that duration and stays paused afterward. The same button is available when real-time mode is paused. Manual steps use the same spawning, signals, routing, collision checks and stopped-time statistics as continuous running. Time scale does not multiply a manual step. Selecting either clock mode pauses the simulation and clears unprocessed pending time; press Run explicitly to resume real time.

A requested duration is divided into equal physics ticks of at most 1/120 second, and the engine retains its collision substeps. Larger requested durations do not skip collision checks or reduce physics accuracy. They can take longer than their requested duration in wall-clock time. Processing is spread over rendered frames with an approximately 8 ms work budget; an individual expensive physics tick may exceed that budget. The progress bar shows advanced/requested simulation time. **Cancel remaining step** stops future processing while keeping the time already simulated. Reset, map changes and geometry-edit tools cancel pending work. Signal timing edits remain live between processed frames. When paused with no pending work, the viewer redraws at roughly 15 FPS to reduce idle CPU use.

The viewer runs a fixed 120 Hz simulation clock, with physics substeps no larger than 0.01 s. Render frames cap catch-up at 0.1 real seconds, and minimizing pauses the clock. Vehicles accelerate from rest toward their sampled speed. Corners use tangent-continuous circular fillets: the vehicle translates and changes heading together, carrying its speed through an unobstructed turn. Preferred radius is `max(1 m, 0.8 * body length)`, limited by adjacent segment lengths and reduced where necessary to fit the mask. Circular centerlines are sampled at up to 5 cm or one degree, with heading interpolated continuously between samples. Travel left over at a sample boundary is consumed on the next segment within the same physics step. A replan from a moving pose uses a tangent-continuous Bezier entry connector. Swept convex geometry bounds every interpolated body movement, preventing tunneling through walls, other bodies, or stop lines. Older vehicles get first admission to contested maneuvers.

Vehicles spawn aligned with their first route segment. Curved paths are checked against the mask using the entire oriented vehicle body. Before entering a corner, vehicles reserve the approach corridor and the curved-body envelope, including pairwise clearance. A failed reservation for a future turn no longer stops a vehicle immediately: it advances along the clear approach, braking toward the turn entry if the reservation remains unavailable. It cannot enter the unreserved arc. Every actual step still checks physical bodies, preferred pairwise clearance, signals and other active reservations, so a conflicting swept path can require stopping even when the current vehicle bodies are farther apart than their preferred gap.

Approach reservations shrink from the owner's current position as it moves and clear on entry to the arc, releasing vacated approach road for following vehicles. The curved-body envelope and committed path remain protected until the arc finishes, except when a validated replacement safely cancels an obsolete local bypass as described above. The pathfinder can plan through spaces that will become available, instead of repeatedly searching around a short-lived turn lock. Failed searches back off up to 15 simulation seconds. Traffic conflicts and red lights can still stop a vehicle, including on an arc; an unobstructed heading change itself does not reset speed.

Standstill detection measures translation in 0.25 m increments, so tiny creeping steps do not conceal a jam. After six seconds without progress, a blocked vehicle can reserve a short reverse maneuver (up to 3 m, at up to 1 m/s), yield, and replan toward its original destination. Both the reverse corridor and its statically reachable exit are checked before committing; every reverse step still obeys mask boundaries, body clearance and traffic lights. A prolonged maneuver wait becomes eligible after 30 seconds. Spawn admission pauses during an unresolved standstill to retain recovery space. Intentional red-light waits propagate through physical queues and do not trigger reverse recovery. The viewer reports yielding-recovery counts and individual signal/maneuver/reversing states.

Detailed navigation uses a heading-aware, footprint-checked A* search, followed by visibility smoothing. Sampling uses the smaller of one mask pixel and 0.5 m. Positive randomized traversal costs produce route diversity; zero variation removes random edge costs. The coarse guide, congestion costs and weighted heuristic mean routes need not be globally shortest. Search is bounded to 12,000 expanded states; a physically possible but unsampled or over-budget route may be rejected. Spawn searches use the static mask and congestion costs; traffic-aware fallback searches include current vehicle footprints and retry periodically. A requested truck that cannot fit is not silently changed into a bike.

This is a geometric traffic prototype: the final collision gate can stop a vehicle immediately if following control does not leave enough room; there is no full vehicle-dynamics/wheelbase model or lane priority. Tight turns can reject a long vehicle even if its centerline fits. Reservation and recovery regressions require the built-in preset's admitted traffic to finish after spawning stops, across several seeds, heavier spawning and a longer run. These checks establish coverage for the preset rather than a mathematical guarantee for arbitrary masks: a fully occupied sealed corridor or an unreachable exit can have no legal maneuver. Congestion, large masks, and repeated route searches can reduce frame rate; the current implementation does not target city-scale traffic counts.

## Engine API and verification

### Negotiated turn space and incremental merging

The viewer enables **Negotiated turns / Yield to turning vehicles**. A nearby conflicting turn requests temporary priority over its continuous swept body corridor, represented by padded pieces about 0.5 m long rather than a single oversized bounding rectangle. Overlapping turn claims are serialized, with older waiting requests first; disjoint turning spaces can proceed concurrently. Ordinary platoon following is retained when followers share the same turn. A straight-through follower on the incoming road must still yield to the turning vehicle's rear swing. Traffic-aware route searches and passing-maneuver validation treat active claimed space as reserved, allowing alternatives around it where practical. Shared road routes may still cross geometrically; their conflicting occupation is separated in time.

The owner brakes to a configurable creeping cap (default 2 m/s), then advances in the existing physics substeps, at most 2 cm of requested translation per 0.01-second step at that cap. It does not need to reserve one empty envelope for the entire turn before moving. Actual swept collision, map-mask, preferred-gap and red-light checks admit every step. Approaching vehicles brake before entering its space and yield until the tail-clearance point. Vehicles already inside are allowed to continue clearing instead of being frozen in front of the owner. A stationary downstream queue facing the exit holds a new turn at its entry; angled neighbors beside it are not mistaken for that downstream queue. Vehicles already committed inside a turn continue clearing when possible. A new vehicle cannot spawn inside an active claim.

Only the owner's own forward progress renews its claim. Two seconds without progress releases the claim and applies a one-second retry cooldown; a 45-second maximum also bounds any claim. Completion, a changed route, a reverse, a signal-slot assignment, removal or disabling the feature invalidates ownership immediately. Stale IDs cannot hold a yield. Close blocked followers inherit their queue's live turn owner, so the back of a legitimate yield queue is not mistaken for an unexplained stop. Legitimate turn/exit waits are protected from unsolicited RTS detours, gravitational forcing and stuck-vehicle deletion, while actual stopped-time telemetry continues. Mutual exit dependencies feed the deadlock detector and can be released by coordinated recovery; an already validated recovery maneuver is not interrupted by a newly negotiated claim.

The vehicle inspector identifies the owner, the vehicle being yielded to, or an occupant clearing its space. Controls expose the creeping cap and the total number of granted turns. Engine access: `setTurnNegotiationSettings(TurnNegotiationSettings)`, `ownsNegotiatedTurn(entity)`, `maneuverYieldTo(entity)` and `negotiatedTurns()`. Engine instances keep this policy off unless configured; the live viewer enables it. Tests cover crossing yields and resumption, mutually conflicting turns, independent concurrent turns, occupants clearing, downstream room, red-light precedence, tug compliance, spawn exclusion, changed routes, abandoned leases and mutual exit waits.

### Front-point gravitational tug, mass and contacts

The viewer enables **Gravitational tug physics** as a recovery assist. After a persistent unexplained standstill (2 seconds by default), a force at the vehicle's nose pulls toward a rolling target ahead along the route. It can move and rotate the body independently of exact path samples; nearby bodies and road edges exert repulsive forces, with a lateral escape bias around a vehicle ahead. Passing guide segments advances the target without snapping the body onto them. Point destinations use a configurable arrival region (default 0.5 m). This is a softened, gravity-like steering potential, not literal astronomical gravity or a crash-damage simulator.

Default assistance is a brief, approximately one-second nudge, followed by a continuous-position reconnect to the road route and a two-second cooldown. Ordinary physical queues and coordinated maneuvers remain under their existing controllers. Forward momentum is retained on reconnect, while the guided tires absorb residual lateral slip. If no static reconnect curve fits, force guidance continues until one can fit. **Use force motion for every vehicle** instead enables continuous force guidance, including open-road driving; it retains the same collision and light constraints. Potential fields can have local equilibria, so this option is not a guarantee that every geometric deadlock has a solution.

Vehicles have mass in kilograms (illustrative defaults including rider/load assumptions: bicycle 100, motorbike 200, car 1,400, truck 10,000, bus 12,000). Edit any selected vehicle's mass in the inspector; it also reports force activity and angular velocity. The body has rectangular rotational inertia `I = mass * (length² + width²) / 12`. The target force is applied at the nose, producing torque about the center of mass. The softened field uses `F = strength * sqrt(mass / 200) * delta / sqrt(|delta|² + 1 m²)`, so heavier bodies still accelerate less. Semi-implicit velocity integration includes damping, lateral tire drag, an acceleration ceiling, a 1 rad/s yaw ceiling and a configurable speed cap (3 m/s by default). Live controls expose strength (newtons at 200 kg), damping, speed cap and activation delay.

Contacts resolve against the **existing minimum preferred-distance buffers** before body penetration. Inelastic normal impulses account for both masses and rotational inertia; symmetric face contacts are averaged to avoid spurious spin. Force-guided neighbors receive equal and opposite impulses. Route-guided neighbors use a finite longitudinal effective mass while their tires constrain lateral motion and yaw. A vehicle legitimately stopped at a red signal acts as an anchored contact. Walls and solid pink dividers remain impassable. All accepted translation and rotation still pass swept road-mask/body checks; a red stop margin prevents a tug from creeping onto the line and then treating itself as already crossing. Real reverse maneuvers clear the old tug velocity before resuming.

Engine access: `setTugSettings(TugSettings)`, `tugSettings()`, `setEntityMass(id, kg)`, `defaultVehicleMass(kind)` and `tugContacts()` (contact-resolution count, not crash count). `Entity` exposes mass, force velocity, angular velocity and tug activity. Engine instances leave force assistance off unless enabled; the viewer enables the conservative recovery mode. Regression tests cover mass-dependent acceleration and torque, passing a waypoint without hitting its coordinates, momentum transfer without buffer penetration, symmetric contacts without artificial spin, red/green queues, solid dividers, pose-preserving disable/reconnect and a stale path anchor. The continuous startup regression enables the viewer's tug settings while retaining its 52-second movement and clearance assertions.

### Vietnamese city preset and smoother movement

The viewer now starts with a tunable Vietnamese city demonstration preset: 80% motorbikes, 14% cars, 3% bicycles, 2% buses and 1% trucks. Motorbikes sample a 7 m/s cruising speed and a 0.35 m preferred gap, cars 6 m/s and 1 m; all retain Gaussian variation and the existing smaller-pair-preference collision rule. These are illustrative simulation assumptions, not measured citywide parameters. Motorcycle-heavy lateral lane sharing and class-specific behavior are motivated by [Hanoi trajectory research](https://www.mdpi.com/2624-8921/8/8/185); calibration to a particular street still requires its counts and trajectories.

**Urban traffic behavior** offers a live **Smooth mixed traffic** switch, two-wheeler following headway, conflict-prediction horizon and filtering-speed cap. The reset button reapplies the preset on the current map. Existing spawn-mixture and profile controls still work. Headways add a dynamic braking allowance above the hard minimum gap: two-wheelers use 0.65 seconds and larger vehicles 1.1 seconds by default. Curvature-based speed limits look ahead to upcoming bends and brake before them, aiming for a lateral acceleration of 1.8 m/s². Crossing-traffic forecasts consider 1.2 seconds of near-term motion; a deterministic older-vehicle priority breaks symmetric crossing conflicts. This is a simulation negotiation heuristic, not a model of legal right-of-way at every junction. Every actual movement still passes swept collision, road-mask and traffic-light checks.

Two-wheelers can seek tighter checked passing corridors, including past stopped signal traffic when their entire proposed maneuver respects the stop line. Their active local detours are capped at 3 m/s; sampled cruise speeds remain unchanged. Following control stays active while detouring. Lane dividers remain solid. Signal-slot spreading continues to handle vehicles approaching red lights side by side. The preset checks local routes every 0.35 seconds, refreshes moving endpoint routes every 1.2 seconds, observes unexplained stops for 0.6 seconds and retries failed recovery after 1.5 seconds. Fleet recovery reuses working routes and searches again for unexplained stalled roots, reducing redundant terrain searches. No physical clearance is waived and no vehicle is teleported during planning.

Engine access: `vietnameseCityProfiles()` and `setUrbanTrafficSettings(UrbanTrafficSettings)`. Engine instances retain generic profiles with urban behavior disabled unless configured; the live viewer enables the preset. Urban regressions cover bend-speed reduction with continuous motion, anticipatory crossing yields, minimum clearances, signal-queue drainage and the actual curved startup map, all with automatic vehicle deletion disabled.

### Parallel collision work and stopped-time monitoring

**Untangle stopped traffic** is enabled by default in **Performance and stopped time**. The vehicle inspector displays a verified stop reason: actual red/yellow crossing or occupied signal slot, physical vehicle blockage, road obstruction, a planned reverse yield, or an unexplained stop. Cached waiting flags alone cannot justify a stop. The checks use a short swept probe along the current route, current body footprints and the smaller preferred gap; permissive signals retain their route-specific exception. Stops shorter than the configurable one-second observation period are left to ordinary acceleration and following.

An unexplained stop holds simulation time and maps routes for the **entire active fleet** to its original endpoints, with no 12-vehicle limit. Working routes, committed moving turns and legitimate signal queues remain part of the coordinated rollout. The planner tests releasing conflicting future claims for stalled vehicles, replacing their routes from their actual poses, and short reverse yields. Forward candidates run for 1.5 seconds in a private simulation copy; reverse candidates get 4 seconds to reverse and resume. Every stalled root in the selected connected knot must make progress, and a successful forward repair takes precedence over reversing. Independent jams are handled separately, oldest stop first with retry cooldowns, so one unrelated blockage cannot veto another's repair. Only initial repair plans are committed. Actual positions, headings, speeds, signal phases, trip counters and stopped-time statistics do not advance during planning. The viewer excludes this planning work from real-time catch-up. **Untangle stopped traffic now** checks eligible stopped actors; the panel reports mapped fleet routes, passes, repairs and last planning duration.

Circular physical waits are distinguished from ordinary queues: after at least twice the configured stop observation period (minimum 1 second), the engine follows actual short-sweep body blockers to detect cycles without a moving or red-light root. The inspector labels these **Circular vehicle blockage**. Recovery can try different yield vehicles, or a rear-first backup convoy that includes stationary vehicles behind the knot. Convoy planning uses virtual final poses only inside the private planner; real movement still uses current bodies and swept clearance checks. A coordinated backup requires a traffic-aware, checked departure corridor, and retains that exit route after reversing instead of immediately returning to the same pinch point. Recovery previews suppress incidental RTS replans so they validate only proposed routes. Angled neighbors beside an urban vehicle must be meaningfully ahead before following control can treat them as leaders, preventing mutual false following. Normal signal waits and ordinary queues continue under normal controls.

Regressions include angled two-wheeler deadlocks, red-slot protection and a seed-42 continuous-spawn reproduction of the startup screenshot. At 52 seconds the latter requires at least 75% of active vehicles to be moving or participating in a verified live turn negotiation, with no unexplained upstream stop lasting 3 seconds. It then requires at least 20 arrivals and half the admitted traffic to have arrived by 60 seconds, followed by eventual arrival of every admitted vehicle, with deletion disabled and physical clearance checked throughout. Courtesy yields intentionally count as legal waits; stale ownership cannot satisfy the check. The old screenshot failure (16 arrivals out of 33 admitted at 60 seconds, with no valid turn ownership) still fails these assertions.

Cooperating vehicles admit their motion incrementally using swept body checks instead of holding conflicting whole-turn corridors. Normal signal waits remain under signal-queue control. The exact smaller preferred distance is inclusive (geometry tolerance 0.0000001 m). Close rotating sweeps are subdivided when their conservative envelope is inconclusive. If an existing pair is already inside its preferred gap, a recovery move may only increase separation without dipping below its starting gap; body overlap remains forbidden, including for zero preferred distance. If no safe candidate works, the original traffic stays in place and retries after a cooldown. This bounded search can briefly pause the viewer on complex maps; it does not guarantee a solution to physically blocked roads. The separate stuck-leader removal policy remains configurable.

Engine access: `stopReason(entity)`, `stopReasonName(reason)`, `lastFleetRouteCount()`, `setTrafficRecoverySettings({enabled, stopSeconds})`, `planStoppedTraffic(force)`, `trafficRecoveryPasses()`, `trafficRecoveryRepairs()`, `lastTrafficRecoveryMilliseconds()` and `totalTrafficRecoverySeconds()`.

**Performance and stopped time** provides a live collision-worker count (1–4, capped by hardware concurrency). One worker selects serial execution. At 32 or more active vehicles, collision queries collect nearby bodies and reservations; batches with at least eight candidates can run read-only geometric checks on a persistent worker pool. All workers finish before the movement is committed. Movement, spawning, routing and reservation changes retain their ordered execution, preserving collision admission and seeded behavior. Small or sparse fleets stay serial to avoid scheduling overhead. This is partial multithreading, not a background simulation thread: expensive route searches can still hold up the viewer, and a speedup is workload-dependent. `parallelCollisionBatches()` reports actual dispatched batches. The engine instance must still be called from one owning thread.

A vehicle accumulates **stopped seconds** whenever its actual displacement during a physics substep averages at most 0.05 m/s. This includes red lights, queues, failed movement and initial acceleration below the threshold. Moving in reverse counts as moving. Durations use simulation seconds; pause adds nothing and time scale changes their rate relative to wall-clock time. Accuracy is at physics-substep resolution (up to 0.01 seconds).

The fleet panel and workspace show the arithmetic **mean (average)**, minimum and maximum of each vehicle's cumulative stopped seconds, plus a summed total and population counts. Zero-stop vehicles are included. **Include finished / removed trips** is on by default; disabling it selects active vehicles only. Finished-trip aggregates remain after vehicles leave the map without retaining full entity histories. Empty populations display zero. The vehicle inspector shows total stopped time, current uninterrupted stop, longest uninterrupted stop and elapsed trip time. Resetting/reloading the simulation clears these statistics.

**Remove stuck queue leaders** is enabled by default, with a configurable 30-second timeout. The engine checks stopped queues twice per simulation second, follows close forward blockers to the front, and deletes one stationary blocker holding up at least one other vehicle. Its actual movement must remain at or below 0.01 m/s throughout the observation period. Normal red/yellow waits and queues behind them are protected and get a fresh observation period after the light changes. For opposing/circular deadlocks with no unique front, the blocker with most direct followers is selected, with oldest ID breaking ties. A two-second cooldown lets the remaining traffic advance before another removal. Isolated stopped vehicles and moving queue leaders are left alone. Changes to this policy restart observation timers.

The UI reports the removal count and last removed vehicle ID. Removing a vehicle releases its physical body and maneuver reservations. Deleted trips are counted separately from successful arrivals: `removedStuckVehicles()` and `lastRemovedStuckVehicle()` expose the counters; `completed()` still counts arrivals only. **Include finished / removed trips** retains removed vehicles' stopped time in fleet aggregates. `setStuckVehicleSettings({enabled, timeoutSeconds})` configures the policy (1–3600 seconds). Existing physical-recovery drain regressions explicitly disable deletion so they continue requiring every vehicle to arrive; dedicated removal tests cover front-blocker selection, opposing deadlocks, cooldown, red-light protection and telemetry retention.

Engine access: `stopStatistics(includeCompleted)`, `Entity::stoppedSeconds`, `currentStopSeconds`, `longestStopSeconds`, `ageSeconds`, `setCollisionWorkers(count)` and `maximumCollisionWorkers()`. Telemetry regressions exercise red-light waits, resumed motion, completed aggregates, empty populations, real worker execution, error propagation, and serial/parallel trajectory equality for a dense fleet.

The public API is in `include/traffic/Simulation.hpp`. `routingSettings()` / `setRoutingSettings()` control RTS mode, look-ahead, local update interval and congestion weight; `localDetours()`, `globalPlans()` and `navigation()` expose routing statistics. Tests also check sector connectivity through thin portals, unreachable-destination rejection, destination-field cache reuse, local bypasses, and speed matching in a lane too narrow to pass.

Example:

```cpp
auto map = traffic::Map::fromPng("examples/curved-mask.png", 0.5);
traffic::Simulation simulation(std::move(map), 42);
auto bike = simulation.profile(traffic::VehicleKind::Bike);
bike.width = {0.60, 0.05};
bike.distance = {0.40, 0.10};
simulation.setProfile(traffic::VehicleKind::Bike, bike);
simulation.setTrafficLights({{{30, 22}, {30, 38}, 10, 2, 12, 0, true}});
simulation.spawnRandom();
simulation.tick(1.0 / 120);
```

`spawn(Cell, Cell, variation, kind)` accepts mask-pixel indices; `spawnAt(Vec2, Vec2, kind, variation)` accepts meter coordinates. `Entity::center`, `goal`, and `path` use meters; `heading` is radians. `completed()`, `replans()`, `seconds()` and `entities()` expose runtime state. Masks are immutable inside a running simulation; construct a new simulation to edit the mask. Earlier unused sketches in `include/src` are not part of the engine.

The command-line demo accepts `[PNG] [seconds] [metersPerPixel]` (one-second ticks, default scale 0.5 for imported PNGs):

```sh
build/traffic_demo examples/curved-mask.png 30 0.5
```
