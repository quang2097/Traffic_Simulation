# Traffic Lab — Native and SUMO

**Shared Tr for normal lights:** In **Traffic lights → Normal lights: shared Tr**, choose the junction, set the all-red duration and click **Enable shared Tr for junction**. Linked groups alternate through green/yellow and a full shared Tr before the next green. The timer works in Native and SUMO, displays a live countdown and saves in `.signals`. Red times and offsets are calculated while enabled; disabling restores independent timing. Applying Tr pauses traffic so you can review the groups before Play. [Normal Tr controls](docs/DUAL_ENGINE_UI.md#shared-tr-for-normal-traffic-lights).

**train (1).ipynb weights:** DuelingDQN also recognizes its embedded safety-mask model (`min_green_t`). Load the exported `traffic_policy.pt` with **Auto** or **DuelingDQN**, or its ONNX file with **DuelingDQN**. The exported yellow/Tr/minimum-green action mask is preserved. Match the supplied notebook's **Tr 20 s / yellow 3 s / minimum green 5 s** in Training data before enabling policy control. [Masked policy details](docs/RL_CONTROLLER.md#train-1ipynb-embedded-safety-mask-weights).

**train.ipynb policy:** The RL controller now supports its dueling DQN trained with CQL followed by Double-DQN. Load `traffic_policy.pt` with **Auto** or **DuelingDQN**. Its ONNX export also works; choose **DuelingDQN** explicitly or use Auto's compatible joint DQN contract. Embedded normalization, 28-feature queue/wait observations and all three hold/switch actions are preserved. The previous DQN export remains supported. See [model format and action mapping](docs/RL_CONTROLLER.md#trainipynb-cql-followed-by-dueling-double-dqn).

**Append training data:** In **Training data**, choose your existing dataset folder and leave **Append to existing dataset** enabled. Each finalized run is added to the folder's combined `transitions.jsonl`, with a `session_id` identifying its own CSVs, metadata and scenario snapshot subfolder. Earlier records are preserved. Disable the checkbox to require a new empty dataset folder. The batch/live runner also appends when reusing `--output` (use `--append false` for a new dataset). See [dataset append and episode layout](docs/TRAINING_DATA.md#append-runs-to-one-dataset).

**Manually delete a vehicle:** Click a vehicle on the map, then press **Delete** or use **Delete vehicle (complete trip)** in the inspector. This works while running or paused, in Native and SUMO. Only the selected vehicle is removed; it counts as one completed trip, including its stopped-time statistics, without advancing the clock. The Delete shortcut is inactive while typing, dragging controls, using a map tool or a popup. Live statistics, Results and CSV schema 3 report `manually_completed_trips` separately; total completed trips and throughput include them, while `destination_completed_trips` excludes manual and green-clearance completions. Choose a new comparison CSV if an older file has a different header.

**Complete a junction on green:** In **Traffic lights**, select a light and open **Junction completion**. Its downstream connected junction is selected automatically when the signal has a road-station link; otherwise choose **Junction to clear**. Enable **Complete junction vehicles on green** and adjust **Clear radius (m)** to cover the junction. The orange circle shows the affected area. Each change from red/yellow to green removes every vehicle whose center is inside that circle and counts it as completed, retaining stopped-time statistics. It fires once per green change, so vehicles entering during that green remain in the simulation. Outside queues, other junctions and pending SUMO insertions are preserved. Works in Native and SUMO, including external/RL phase control. Save the map/network's `.signals` companion to preserve the setting. The option is off by default; installing or enabling an already-green light does not clear traffic. Results CSV schema 2 reports `completed_on_green` and `destination_completed_trips` separately, with both included in total completed trips and throughput. Choose a new CSV if an older comparison file has a different header.

Native lane changes are conservative: slower evaluation, a 15-second cooldown, substantial speed gains, and no automatic keep-right weaving. A vehicle that stops during a merge returns fully to its original lane and disables further lane changes for that trip. The original return position is protected during the merge so rollback has a clear fallback.

**Optional overlap recovery:** In **Native simulation → Native recovery**, enable **Allow vehicles to overlap when stuck** to clear persistent blockages. Normal spacing applies first; after **Reservation timeout** (15 seconds by default), one vehicle releases stale reservations. If still stopped after **Extra wait before overlap** (3 seconds by default), it may pass through other vehicles at low speed until clear. Road boundaries, red lights, and priority yields still apply. This option is off by default and works independently of **Release stale reservations**. Turning it off prevents new overlap escapes; a vehicle already overlapping finishes separating. Intentional overlaps remain visible in collision statistics.

**Save results for comparison:** Open **Results** (also **File → Simulation results**), enter a run label and notes, then click **Save snapshot to CSV**. Each click appends one row to the chosen file; the default is `results/comparison.csv` relative to the application's working directory. The panel shows the absolute saved path. Change settings, reset traffic, run for the same simulated duration, and save to that same CSV with a different label. Open it in Excel or another spreadsheet application to compare completed trips/hour, stopped seconds, active/pending/completed/removed vehicles, speed, native collisions/overlaps and separate SUMO counters. Rows include UTC save time, a run ID, the seed used at reset, controller, source paths, demand rates, signal timings, vehicle profiles and key recovery settings. Saving neither pauses nor resets traffic. Multiple saves within one run retain its ID; reset or engine activation starts a new ID. Stop averages always include active, completed and removed trips, including zero-stop trips; pending vehicles are reported separately. Settings are snapshots at save time and paths do not save design edits. Save the PNG/network separately when preserving a scenario. Existing CSVs with incompatible headers or incomplete final rows are rejected without modification.

**Training data** records camera-limited queue categories, phase/red ages, cumulative per-signal wait statistics, randomized node demand and RL transitions. Hold/request control keeps a phase until requested or the maximum-red threshold forces yellow followed by a full all-red **Tr**. Use `build/traffic_training_ui.exe`, the batch `traffic_training` runner, or the live Python environment. See [training/data export guide](docs/TRAINING_DATA.md).

**RL controller** loads exported ONNX/TorchScript policies for two synchronized signal groups (up to four physical lights). Each agent observes its group's upstream packing density and chooses a green duration; yellow and clearance are handled by the shared cycle. Model-family auto detection falls back to a selection dialog for MAPPO, IPPO, QMIX, IDQN, DQN, MPLight, CoLight, PressLight or MA2C. See [policy formats, observation/action contract, and runtime setup](docs/RL_CONTROLLER.md).

The C++/ImGui application includes both implementations. Open **Native simulation** or **SUMO simulation**, then click **Use Native** / **Use SUMO**. Browsing a section does not change engines. Activation resets vehicles and counters, preserves the common map, signals and vehicle profiles, and pauses.

- **Native** runs the previous C++ traffic controller, including native lanes, tapered widths, restriction sections, recovery controls and free junctions.
- **SUMO** runs actual headless Eclipse SUMO 1.28.0 through C++ TraCI for lane traffic, while keeping native free-junction handoffs. See [SUMO import boundaries](docs/SUMO_BACKEND.md).
- **Help → User manual**, the toolbar's **User manual** button, or **F1** opens the searchable in-app guide. Instruction paragraphs have moved there; the sidebars contain controls and live data.
- An active map tool shows **Cancel (Esc)** at the bottom-left of the map. It cancels connection, sever, sketch, insertion, painting and line-placement modes without changing committed geometry. Sketches also support Undo last point.
- Roads support up to **32 lanes per direction**. In a node popup, **Lane exits** assigns each incoming lane to specific outgoing node IDs and lane numbers. **File → Examples → Seven-lane routing** demonstrates this. See [lane connections and directional signals](docs/LANE_CONNECTIONS.md).
- Lane exits opens a visual editor beside the map: select one incoming lane by number, then click outgoing lanes or their numbered buttons. Gold marks the source; teal arrows show only its chosen exits. Apply or discard before switching source lanes. Links cross free road-mask space even when roads have no common junction. Birth chooses only reachable trip destinations. Fixed-size node badges stay visible above lights and traffic.
- Play, Step and manual spawning require explicitly assigned exits for every non-destination lane. The notification lists missing node/road/lane settings. Set per-target-lane priority in **Lane exits**; **Native simulation → Junction priority** offers optional starvation relief, off by default.
- **Place signal node on road** inserts a station on the road guide. Its popup creates a perpendicular light and links an allowed-exit line. All lights now have an **OUT** direction that obeys the signal and a reverse **IN** direction that passes freely; use **Reverse IN / OUT** to reverse them.

```powershell
# Needed only for SUMO mode if its runtime is not already installed:
powershell -ExecutionPolicy Bypass -File scripts/install-sumo.ps1
cmake -S . -B build -DTRAFFIC_UI_OUTPUT_NAME=traffic_semantic
cmake --build build --target traffic_ui sumo_ui_smoke sumo_integration_tests lane_connection_tests semantic_lane_tests junction_priority_tests -j 4
ctest --test-dir build --output-on-failure
.\build\traffic_semantic.exe
```

Native mode does not start a SUMO process. SUMO searches `SUMO_HOME`, `sumo-runtime/sumo` beside the executable, then this project's `build/sumo-runtime/sumo`. A missing runtime does not silently switch engines: choose Native explicitly if desired. Python/pip is only the runtime installer; the running application and bridge are C++.

Use File for opening/saving PNG maps and .nodes networks. Keep their .signals companions together. The common vehicle profiles, independent spawn-node rates, light timings and detector controls work with the active implementation. The toolbar identifies that engine. Model-specific native controls appear only in its own simulation section.
